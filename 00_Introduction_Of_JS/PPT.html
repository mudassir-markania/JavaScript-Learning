The History of JavaScript

  • 1995: The web was entirely static. Netscape Communications wanted to add dynamic behavior.
  • Brendan Eich was hired to embed a scripting language into Netscape Navigator.
  • He famously wrote the first prototype in just 10 days!
  • Name evolution: Mocha → LiveScript → JavaScript.

ECMAScript Standardization

  • Netscape submitted JS to ECMA International (1996) to create a standard specification, called ECMAScript.
  • ES1 (1997) - First Edition.
  • ES5 (2009) - Brought JSON support, strict mode, and array methods.
  • ES6 / ES2015 - The biggest update ever (let/const, classes, arrow functions, promises).
  • ES2016 - Present - Annual releases with incremental updates.

The Chrome V8 Engine

  • Early JavaScript was considered slow because it was purely interpreted.
  • In 2008, Google released Chrome featuring the open-source V8 Engine.
  • V8 compiles JS directly to native machine code just-in-time (JIT compilation).
  • This drastically improved performance, paving the way for complex web apps!

Node.js: JS Everywhere

  • 2009: Ryan Dahl realized V8 was so fast it could be used outside the browser.
  • He extracted V8, bound it to C++ APIs, added an event loop, and created Node.js.
  • This allowed developers to write Server-side JavaScript.
  • The same language could now be used for the entire full-stack!

The Framework Era

  • As apps grew, writing vanilla JS became difficult to maintain.
  • Early 2010s: AngularJS & Ember brought MVC concepts to the frontend.
  • 2013-2014: React (Facebook) & Vue.js popularized component-based architecture.
  • Modern Era: Meta-frameworks like Next.js, Nuxt, and SvelteKit blur the lines between frontend and backend.

V8 Engine Concepts

  • Parser: Converts JS source code into an Abstract Syntax Tree (AST).
  • Ignition: Generates unoptimized bytecode from the AST.
  • TurboFan: Takes frequently executed bytecode and optimizes it into blazing-fast machine code.
  • Memory Heap: Where dynamic memory allocation happens.
  • Garbage Collector: Automatically frees up unused memory.

Execution Context

  • An abstract environment where JS code is evaluated.
  • Global Context: Default environment. Creates `window` and `this`.
  • Function Context: Created brand new every time a function is called.
  • Two Phases:
       1. Memory Creation (Variables hoisted)
       2. Execution (Code runs line-by-line)

The Call Stack

  • JavaScript is single-threaded; it has only one Call Stack.
  • It operates on a LIFO (Last In, First Out) principle.
  • When called, a function is pushed to the stack.
  • When returned, it gets popped off the stack.
  • Stack Overflow occurs with too many calls!
