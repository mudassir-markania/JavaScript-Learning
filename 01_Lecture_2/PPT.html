Data Types in JavaScript

Primitive (Value Types)

Immutable data. Values are stored directly in memory (the Stack).

  • String: "Hello World"
  • Number: 42, 3.14
  • Boolean: true, false
  • Undefined: Variable declared but has no value
  • Null: The intentional absence of any value
  • Symbol: Unique identifiers (added in ES6)
  • BigInt: Extremely large integers

Non-Primitive (Reference)

Mutable data. Memory addresses are stored, not the actual values (the Heap).

  • Object: Collections of key-value pairs 
    { name: "John", age: 30 }
  • Array: Indexed lists (technically a type of Object) 
    [1, 2, "three", true]
  • Function: Reusable code blocks (also Objects!)

Variables in JavaScript

How we store data. Before ES6, we only had var. Now we use let and const.

var

  • Scope: Function or Global scoped
  • Re-declare: Yes (can cause bugs)
  • Update: Yes
  • Hoisting: Initialized as undefined
  • Legacy - Avoid using in modern JS.

let

  • Scope: Block scoped {}
  • Re-declare: No
  • Update: Yes
  • Hoisting: Temporal Dead Zone (Error)
  • Use when a value will change.

const

  • Scope: Block scoped {}
  • Re-declare: No
  • Update: No (cannot reassign)
  • Hoisting: Temporal Dead Zone (Error)
  • Use by default for everything else!

The Ultimate Challenge

Variables & Data Types Combined

Read the code below. What will be logged to the console, and why?

const user = { name: "John" };
let age = 30;

// Assignments
const newUser = user;
newUser.name = "Jane";

let newAge = age;
newAge = 31;

// What gets logged?
console.log(user.name); // ???
console.log(age);       // ???
Answer:
• user.name is "Jane" (Objects are Reference types. newUser and user point to the same memory).
• age is 30 (Numbers are Primitive types. newAge is an entirely separate copy in memory).

Rules for Naming Variables

The Core Rules

  • Must start with a letter, an underscore (_), or a dollar sign ($).
  • Cannot start with a number.
  • Cannot contain spaces or hyphens (-).
  • Case Sensitive: Age and age are two completely different variables!
  • Cannot use JS Reserved Words (e.g., let, const, function).
  • Best Practice: Use camelCase (e.g., firstName).

Examples

✔ Valid Names

let firstName = "John";
let $score = 100;
let _privateData = true;
let user123 = "active";

✖ Invalid Names

let 1stName = "John";  // Starts with number
let first name = "J";  // Contains space
let first-name = "J";  // Contains hyphen
let let = 10;          // Reserved word

Pro Tips

Best Practices

1
Default to const

Use const by default. Only use let when you know the value must change (like loop counters). Avoid var entirely.

2
Write Descriptive Names

Avoid single-letter variables like x or data. Use clear names like userCount or isLoggedIn.

3
Initialize Immediately

Whenever possible, assign a value at the same time you declare a variable. This prevents accidental undefined bugs.

4
Avoid Global Scope Pollution

Keep variables constrained inside functions or blocks {}. Global variables can cause unexpected collisions in large codebases.

Pro Tips

Industry Naming Conventions

1
Booleans: Prefix with a Question

Prefix with is, has, can, or should.
✔ isLoggedIn, hasError | ✖ loginStatus

2
Arrays: Pluralize

Use plural nouns rather than appending "list".
✔ users, activeTickets | ✖ userList

3
Global Constants: UPPER_SNAKE_CASE

Use all caps with underscores for hardcoded values.
✔ MAX_RETRIES = 3, API_BASE_URL

4
Functions: Action Verbs

Start function names with a verb.
✔ getUser(), calculateTotal() | ✖ userData()
