Equality Operators

Q: What is the main difference between == (loose equality) and === (strict equality)?

Answer: == compares only values (performing type coercion if needed), while === compares both value AND data type. Always use ===!

Lecture 5 Recap  2/6

Logical Operators

Q: Which logical operator returns true ONLY if ALL conditions are true?

Answer: The AND operator &&.

Lecture 5 Recap  3/6

Ternary Operator

Q: Convert this simple if/else into a single line using the ternary operator: if (age > 18) { type = "Adult"; } else { type = "Minor"; }

Answer: let type = age > 18 ? "Adult" : "Minor";

Lecture 5 Recap  4/6

Switch Statement

Q: What happens if you forget to include a break statement at the end of a case block?

Answer: The code "falls through" and executes the next case(s) automatically, regardless of whether they match the condition.

Lecture 5 Recap  5/6

Truthy and Falsy

Q: Which of the following values are considered "falsy" in JavaScript? 0, "0", "", false, [], null

Answer: 0, "", false, null. The string "0" and empty array [] are truthy!

Lecture 5 Recap  6/6

Else If Ladder

Q: In an if / else if / else chain, how many blocks can execute when multiple conditions are true?

Answer: Only ONE block! JavaScript executes the FIRST block where the condition evaluates to true and skips the rest of the chain.

Solution

Step-by-Step Implementation


// Given Variables
let customerName = "  Mudassir  ";
let rawAge = " 17 ";
let rawTickets = " 3 ";
let isStudent = true;
let isWeekend = true;
let isMember = false;
let movie = "Avengers: Endgame";

// 1. Customer Information
customerName = customerName.trim();
let age = Number(rawAge.trim());
let tickets = Number(rawTickets.trim());
let bookingID = Math.floor(Math.random() * 90000) + 10000;

// 2. Customer Category
let category = age >= 18 ? "Adult" : "Minor";

// 3. Base Ticket Price
let basePrice;
if (age < 5) {
    basePrice = 0;
} else if (age <= 12) {
    basePrice = 8;
} else if (age <= 17) {
    basePrice = 12;
} else {
    basePrice = 18;
}
let ticketPrice = basePrice * tickets;

// 4. Student Discount
let studentDiscount = 0;
if (isStudent && age >= 13 && age <= 25) {
    studentDiscount = ticketPrice * 0.20; // 20% off
}

// 5. Weekend Charge
let weekendCharge = 0;
if (isWeekend && category === "Adult") {
    weekendCharge = 3 * tickets; // $3 per ticket
}

// 6. Membership Discount
let memberDiscount = 0;
if (isMember || tickets >= 3) {
    memberDiscount = ticketPrice * 0.10; // 10% off
}

// 7. Calculate Total
let finalAmount = ticketPrice - studentDiscount - memberDiscount + weekendCharge;

// 8. Booking Type
let bookingType = tickets >= 5 ? "Group Booking" : "Regular Booking";

// 9. Concession Offer
let concession;
switch (true) {
    case finalAmount === 0:
        concession = "Free Popcorn 🍿";
        break;
    case finalAmount <= 20:
        concession = "50% Off Snacks 🥤";
        break;
    case finalAmount <= 50:
        concession = "Free Soft Drink 🥤";
        break;
    default:
        concession = "No Concession";
}

// 10. Booking Status
let status;
if (age <= 0 || tickets <= 0) {
    status = "Invalid Booking";
} else if (tickets > 10) {
    status = "Maximum 10 tickets allowed";
} else if (finalAmount > 100) {
    status = "Premium Booking";
} else {
    status = "Booking Confirmed";
}

// 11. Final Output
console.log(`================================
       MOVIE BOOKING
================================

Customer: ${customerName}
Movie: ${movie}
Booking ID: #${bookingID}
Age: ${age}
Category: ${category}
Tickets: ${tickets}
Booking Type: ${bookingType}

Ticket Price: $${ticketPrice}
Student Discount: -$${studentDiscount}
Membership Discount: -$${memberDiscount}
Weekend Charge: +$${weekendCharge}
Final Amount: $${finalAmount}

Concession: ${concession}
Booking Status: ${status}

================================`);

Non-Primitive Types

Introduction to Objects

So far, we've learned Primitive Types (Value Types) like Number, String, Boolean, Undefined, and Null. Now, we introduce the Non-Primitive Type (Reference Type):

  • There is only ONE main non-primitive type in JavaScript: The Object.
  • All other complex structures (like Arrays and Functions) are just special types of Objects behind the scenes!

Object Literals

Creating an Object

We create an object using curly braces {}. Inside, we store data as Key-Value pairs separated by commas.


// Creating an empty object
const emptyUser = {};

// Creating an object with properties
const user = {
    firstName: "Akash",
    lastName: "Singh",
    age: 26,
    city: "Bangalore"
};

Working with Objects

Accessing & Updating Values

Dot Notation

The most common and simple way to access or update properties.

Bracket Notation

Used when keys have spaces/dashes or when using variables as keys.


// 1. Dot Notation
console.log(user.firstName); // "Akash"
user.age = 27;               // Updating a value

// 2. Bracket Notation (keys are actually strings behind the scenes!)
console.log(user["lastName"]); // "Singh"
user["is-student"] = true;     // Dash requires quotes/brackets!

// 3. Using a variable as a key
let myKey = "city";
console.log(user[myKey]);    // "Bangalore"

Behind the Scenes

Reference Types in Memory

Crucial Concept: Objects are Reference Types. Variables don't hold the actual object; they hold the Memory Address pointing to where the object lives in RAM!


const user1 = {};
const user2 = {};

// Why is this false?
console.log(user1 === user2); // false!

// Because user1 points to Memory Address #218573
// And user2 points to Memory Address #218575
// JavaScript compares their ADDRESSES, not their contents!

Advanced Objects

Nested Objects

An object's value can be another object! In memory, this just creates a chain of addresses linking the objects together.


const user = {
    firstName: "Adarsh",
    address: {
        city: "Bangalore",
        state: "Karnataka",
        moreDetails: {
            weather: "Nice",
            population: "13 Million"
        }
    }
};

// Accessing deeply nested data
console.log(user.address.moreDetails.weather); // "Nice"

Object Mutation

The const Mystery

Question: Can we change an object declared with const?
Answer: YES! But why?


const user = { name: "Anurag", age: 25 };

// We CAN modify, add, or delete properties:
user.mobileNumber = 1234567890; 
user.name = "Rahul"; 
// ✅ This works perfectly!

// We CANNOT reassign the entire variable:
user = { name: "Adarsh" }; 
// ❌ ERROR! Assignment to constant variable.

💡 Why? const only locks the Memory Address the variable points to. It does NOT lock the contents inside that address!

Protecting Objects

Object.seal()

What if you want to allow modifying existing properties, but prevent anyone from adding new ones or deleting them?


const user = { name: "Anurag", age: 25 };

Object.seal(user); // 🔒 The object is now sealed!

// Modifying existing properties works:
user.name = "Rahul"; // ✅ Success! Name is updated.

// Adding or deleting properties fails:
user.isGraduate = true; // ❌ Ignored (or Error in strict mode)
delete user.age;        // ❌ Ignored

Ultimate Protection

Object.freeze()

What if you want an object to be completely immutable? No changes, no additions, no deletions.


const user = { name: "Anurag", age: 25 };

Object.freeze(user); // 🧊 The object is frozen!

// EVERYTHING fails (ignored or Error in strict mode):
user.name = "Rahul";    // ❌ Cannot modify
user.city = "Delhi";    // ❌ Cannot add
delete user.age;        // ❌ Cannot delete

console.log(user); // Stays exactly { name: "Anurag", age: 25 }
